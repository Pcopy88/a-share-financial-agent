## 3. 已修复的主要问题

1. 江丰归母净利润标签跨行时，能定位同一表格行，不会把同页相同金额当作来源。
2. 报告导出读取本次版本化操作数；重复取 API 数据保留独立快照，不覆盖旧记录。
3. TopK 评分保留真实排名；表格分隔符不会直接导致漏算，也不会把不同单元格数字拼接成命中。
4. Q0/Q1 拒绝已变化的索引/事实；冻结生成只保留实际通过核验的计算和引用。
5. 云端已成功返回后即使后续结构校验失败，也保留已观测 usage；未返回的用量和未配置单价的费用保持未知。
6. Windows 中文路径用实际跨进程测试验证；缺失/损坏索引可从缓存新建恢复版本，成功后才切换。关闭服务先释放向量库再释放进程锁。

## 4. 仍需明确的限制

- **两家云端尚未真实调用。** 用户填写 DeepSeek Key、百炼 Key 及与账户匹配的完整 Embedding 地址后，按 README 先跑探针，再在 live 重新建库。不能直接沿用 mock 向量。
- **当前仅验证 CPU 重排。** 依赖为 CPU PyTorch，未证明 RTX 5070 Ti 的 CUDA 推理可用；本机 CPU 已可运行链路。
- **本机自动 PDF 下载受网络限制。** 一次真实 600519/2024 查询返回 2 个公告候选；下载器因 DNS 地址检查返回 UNSAFE_ADDRESS，未绕过。财务接口实际返回 3 份报表快照、9 个字段，均保持 pending，未伪造 PDF 页码。记录见 `outputs/local_checks/acquisition_live_probe.json`。可以使用本地 PDF 上传。
- **通用新 PDF 的可信取数不能保证一次成功。** 未核验或表格不明确的事实会拒绝计算；交互式纠错页面按原约定后置。摘要向量、Ollama/MLX 生成对照也未纳入本轮。
- **语义正确性仍需独立复核。** 不把引用存在等同于结论受支持；不把“已回答”当正确率。原图 15% / 23% 提升未复现，也未承诺 15 秒内回答。

## 5. 用户接手步骤

1. 按 README 启动默认 mock 模式，可立即查看本地样本、计算结果和来源页。
2. 自行在 `.env` 填写两家 Key、模型/地址，切换 live；密钥不进 Git、日志或题集。
3. 停止服务后跑真实探针和 live 建库，再运行开发题；记录真实返回型号/指纹、实际配置、费用与失败案例。
4. 参数冻结后执行正式留出题及完整对照，独立核验语义、引用和数值，再签署“真实云端问答质量通过”。

**本次可确认的是代码和本地流程交付；云端质量、GPU 性能以及本机网络阻塞的下载环节，均未被包装成已通过。**
